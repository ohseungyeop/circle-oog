# OOG 아키텍처

React 19 / TypeScript / Ant Design 화면은 Spring Boot 3.5.14 / Java 21 API를 호출한다. 업무 데이터는 PostgreSQL의 독립 oog DB와 public 스키마에 저장한다. 초기 서버 포트는 FMS 충돌을 피하기 위해 UI 5175, API 8083, Optimizer 8003이다. Docker/AWS를 사용하지 않는다.

## 모듈

backend/shared-core는 FMS common에서 가져온 ApiResponse, PageResponse, LogisticsCalcUtil을 독립 빌드한다. backend의 OOG 모듈은 프로젝트·화물·장비·규칙·파일·시나리오·감사를 담당한다. optimizer는 API가 전달한 입력으로만 계산하며 DB에 직접 접근하지 않는다.

## 데이터

oog_project → oog_cargo / oog_packing_list / oog_clp_scenario. oog_equipment와 oog_carrier_rule은 별도 테이블이며 시나리오는 화물·제원·규칙 입력 사본과 결과를 함께 저장한다. 공통 감사는 core_audit_history에 저장한다. 원본 Excel은 data/projects/{id}/packing-list에 저장하고 DB에는 상대 경로와 매핑·단위를 기록한다. 화물 Item은 프로젝트 내 유일하고 기본 낙관적 버전은 프로젝트·규칙에 적용한다.

분류 화면은 40HC 계획 기준 OL/OW/OH/OVERWEIGHT를 표시한다. 장비 후보는 각 장비의 물리 제원과 계획 규칙으로 별도 판정한다. V5 oog_carrier_rule_version에서 회사별 선사·장비의 불변 버전과 유효기간을 관리한다. 기간 중복을 차단하고 규칙 미일치 시 명시적인 DEFAULT 대체 또는 거부 정책을 적용한다. 선택·버전 정보를 입력/결과 snapshot에 보존한다.

## 계산

CBM은 FMS 공통 계산의 소수 4자리 반올림을 그대로 재사용한다. AUTO는 OR-Tools CP-SAT로 적층 없는 1열 모델의 장비 대수를 최소화한다. 길이·폭·높이·중량·허용 회전과 수량 보존을 검사하고 장비 대수 우선 및 개별 작업 우선 대안을 생성한다. 개별 작업 우선은 기존 휴리스틱이다. HEURISTIC 선택은 폭/면적/중량 순 first-fit을 사용한다. 비용·Slot Loss·2D 배치·적층 목적함수는 구현 범위 밖이다.

CP-SAT는 최대 128개 포장과 배정변수 18,000개, 기본 3초·설정 0.05~10초로 제한한다. 화물 길이 1 mm와 중량 1 g를 올림하고 장비 한도를 내림한다. 반올림 경계에서 단일 화물 적합성이 달라지는 경우, 솔버 없음·규모 초과·시간 내 해 없음에는 기존 휴리스틱으로 되돌리며 이유를 보존한다. OPTIMAL과 FEASIBLE을 구분하고 bestBound, 실제 방법, 실행시간과 모델을 결과 snapshot에 저장한다. 최적 여부는 이 정수 1열 모델에만 적용된다. 자세한 범위는 [OPTIMIZATION.md](OPTIMIZATION.md)에 기록한다.

## 인증 및 제한

V3부터 DB 사용자·회사·역할·메뉴 권한과 JWT 세션을 사용한다. FMS FmsPrincipal을 원본 그대로 재사용하고 JWT provider는 OOG 독립 issuer/key에 맞게 어댑트했다. Basic 및 Spring 기본 메모리 계정 자동 구성을 제거했다. Access 30분/Refresh 7일, DB Refresh 해시·회전·로그아웃/계정 변경 폐기·현재 계정/회사/역할 상태·메뉴 권한을 적용한다. 회사별 프로젝트·파일·계획·개정·출력을 제한한다. 플랫폼 관리자는 다른 회사 업무를 자동 열람하지 않는다. 공통 DEFAULT 규칙 수정은 회사 1 SUPER_ADMIN과 수정 권한이 필요하다. 추가 FMS 공통 설정과 외부 HTTPS 구성은 별도 범위다.

## 계획 개정과 이력 및 출력

수동 개정은 원본 oog_clp_scenario의 result/input_snapshot을 복사하여 선택 시나리오만 변경하고 신규 행을 저장한다. 현재 화물·Rule을 다시 읽지 않으며 원본과 나머지 시나리오는 보존한다. 수량·snapshot 중량·치수·회전·장비 한도·겹침·잠금을 검증하고 checked exception도 전체 롤백한다. 현재 배정된 화물을 기존 장비로 이동하는 범위이며 신규 장비·미배정 배정·적층은 지원하지 않는다.

이력 API는 실제 JSON으로 매핑·입력·결과·감사 상세를 반환하며 프로젝트 조건과 페이지 제한을 적용한다. 원본 다운로드는 DB의 상대 경로와 실제 파일 경로가 storage 내에 있는지 검사한다. CLP Excel은 저장된 모든 시나리오를 구분해 출력하고 대안끼리 장비 수를 합산해 실제 선적량으로 표시하지 않는다. 3면 도면은 셀 개략도이며 mm 좌표를 별도 보존한다.

## 기능 수치 원본

docs/feature-status.json이 기능 25개의 개발/검증 상태 원본이다. tools/sync-development-status.py가 상태 Markdown과 classpath JSON을 동기화한다. /api/development/status가 기능 ID와 상태 코드를 검사한 후 합계를 계산한다. 완료/미완료와 검증 통과/대기를 분리하며 임의로 완료 숫자를 하드코딩하지 않는다.


## 장비 편집과 전용 PDF

V4 장비 version으로 동시 편집 충돌을 409로 반환한다. 공통 물리 제원은 플랫폼 관리자만 변경하며 기존 저장 계획은 변경되지 않는다. PDFBox로 저장된 모든 시나리오를 한글 PDF와 3면 개략도로 출력한다. OOG_PDF_FONT는 설치된 한글 TTF 경로이며 Windows 기본값은 C:/Windows/Fonts/malgun.ttf다. 글꼴 파일이 없으면 503을 반환한다. 원본 글꼴은 소스에 복사하지 않고 PDF에는 사용 글리프만 포함한다.

## 자동 기본과 수동 선택

ImportDetectionService는 최대 50시트/30헤더행을 검사하며 숫자 크기로 단위를 추측하지 않는다. 유일하고 명확한 후보만 자동 선택하고 확인 후 저장한다. UI는 자동 생성 옵션과 자동/수동 시나리오 선택을 제공한다. 회사 포장 규칙·장비 단가·추정·견적은 V6의 4개 oog_ 테이블에 저장한다. 금액은 BigDecimal이며 대안별 독립 계산, 통화 혼합 거부, 단가 누락 total=null을 적용한다. 포장 추정은 실제 화물을 자동 갱신하지 않는다.

V7 oog_multi_fr_review는 개당/최대32대/원입력 방향의 잠정 배열과 필요조건·규칙·수동 선택을 저장한다. 간격을 연속 지지 길이로 더하지 않고 균등 하중 분담을 가정하지 않는다. V8 oog_engineering_review는 누락 점검과 근거 기록을 저장하는 별도 흐름이다. V9의 계산/결정과 구분하며 과거 검토 기록을 계산 완료로 바꾸지 않는다. 같은 프로젝트·계획과 회사 조건을 검사하고 검토 기록은 ENGINEER/ADMIN/SUPER_ADMIN 및 PLANNING edit 권한으로 제한한다.

V9 oog_engineering_calculation은 저장 계획 화물의 CoG·질량·지지점·한도 입력과 계산 결과를 불변 보존한다. 한 개 강체 화물의 두 지지점 정적 중력 반력·평균 면압, 한 방향 동질 직접 라싱의 미끄럼 필요조건만 계산한다. 확인·추정·부족 입력·한도 초과를 분리한다. oog_engineering_decision은 독립 검토자의 내부 승인/반려/재검토 결정을 버전으로 추가한다. 자기 승인, 추정·누락·한도 초과, 저장 계획 질량 불일치를 차단하고 승인 시 원본 snapshot 일치와 동시 결정 버전을 검사한다. 내부 승인 이후에도 carrierApproved=false와 PRE_PLAN을 유지한다. 전도·동적 반력·다점 분배·구조 강도·전체 운송 경로·선사 기준 적합성은 별도 검토다. [계산 모델 문서](ENGINEERING-CALCULATIONS.md)에 산식·가정·공식 자료를 기록한다.

V10 oog_import_template는 회사·고객·이름별 매핑·단위·중량 기준과 헤더 fingerprint를 불변 버전으로 저장한다. 헤더는 Unicode/공백을 정규화하고 컬럼 순서를 보존한 SHA-256으로 식별한다. 같은 회사·고객과 정확히 일치하는 헤더에서 이름별 최신 템플릿만 추천하고 사용자가 명시적으로 적용한다. 수동 override와 최종 확인을 유지하며 단위가 없는 자료에 숫자 크기로 단위를 부여하지 않는다. 현재 테이블은 core_ 8개·oog_ 16개·Flyway 원장 1개다.

사전 견적 Excel/PDF는 oog_quotation의 저장 input_snapshot/result를 출력한다. 대안별 금액·단가 버전·수동 근거·누락 상태를 구분하고 대안 금액을 합산하지 않는다. 현재 회사 단가 변경은 과거 출력에 반영하지 않으며 화물 미배정·미확인 비용·사전 견적 상태를 보존한다.

verify-all.ps1은 독립 oog DB를 확인한 후 빌드/서버 갱신/순차 회귀/숫자 비교를 실행한다. 검증 fixture는 정확한 UUID/테스트 회사에만 생성·정리한다. 불변 테이블 fixture 정리는 배타 잠금과 트리거 일시 변경·복구를 같은 트랜잭션 안에서 수행한다. verify-status.py는 문서 원본과 실행 API를 비교하고 실제 검사 수를 취합한다.


## v0.7 확대 공학 모델과 코드 검증

`ExpandedEngineeringService`는 CTU 2014 운송 프로필 또는 명시한 사용자 계수를 구간별 네 방향으로 평가한다. 최소 법선력과 별도로 확인한 최대 압축 계수를 사용한다. 3~12개 공면 압축 스프링의 접촉 집합과 비침투/평형을 검증하고, Dykstra의 affine 평형/Coulomb 원판 교차로 X/Y 힘과 yaw를 만족하는 패드 접선력을 찾는다. 증거를 못 찾은 반복 한도는 불가능 증명과 구분한다. 실제 선박 CSS 계수·풍/해수/들림·충격 시간 이력과 결합 유연 구조는 이 모델 밖이다.

패드 반력을 단순 보의 점하중에 연결해 일정 EI Euler–Bernoulli의 선형 중첩으로 굽힘 응력, 유효 면적 평균 전단, 끝단 반력과 최대 처짐을 구한다. 양의 점하중에서 처짐 기울기의 단조성을 이용해 최대 위치를 이분 탐색한다. 모델과 가정·근거·원본 계획을 기존 공학 계산 원장에 불변 저장하며 독립 결정에서도 PRE_PLAN을 유지한다.

프런트는 Vitest/jsdom에서 실제 React/AntD 컴포넌트의 동작을 검사한다. 브라우저 엔진이나 Playwright는 실행하지 않는다. 실제 API는 독립 oog DB에서 별도로 검사하고 상태 합계와 소스 해시를 기록한다.


## 2026-10-14 장비 계열과 공개 선사 자료

기본 DB 장비는 5종이다. 분석/휴리스틱/CP-SAT는 제원과 규칙이 함께 등록된 추가 코드를 후보에 포함한다. 폭 때문에 필요한 수평 회전도 수정했다. 신규 타입 생성 화면과 냉동/탱크 전용 모델은 미구현이다. 공개 선사 출처 3개와 Hapag FR 표 8개 열을 읽기 전용 검토 API에 연결했다. 수치 충돌 열은 차단하고 외삽·자동 승인·자동 제원 반영을 하지 않는다. 세부 근거와 범위는 [PUBLIC-CARRIER-REFERENCES.md](PUBLIC-CARRIER-REFERENCES.md)를 참조한다. 브라우저 검증은 실행하지 않는다.


## 2026-10-14 장비 등록과 반입 개구부

장비 등록 화면/API가 물리 제원과 DEFAULT 규칙 및 확인 근거 감사를 한 트랜잭션으로 생성한다. 플랫폼 관리자만 생성하며 코드 충돌/잘못된 비율/닫힌 면 초과 허용을 거부한다. 개구부 검토는 MASTER 조회 권한으로 선언된 유효 개구부의 DOOR/TOP/SIDE 직사각형 단면과 면당 여유를 검사하며 수평90도 후보를 비교한다. 내부 이동 경로/인양/선사 승인 및 저장 계획 자동 변경은 제외다. 기존 미완료 큰 항목을 E01 실제 증빙/승인, E04 확대 구조, S01 냉동·탱크 전용 운용으로 분리하고 M03/M04를 추가했다. 확장 기능 정의는 전체35·완료32·미완료3이며 과거31개 집계는 당시 범위다.


## 계획별 증빙 보관과 문서상 결정

E01의 소프트웨어 범위를 확장했다. 기존 oog_engineering_review의 EVIDENCE_FILE 기록으로 계획·회사에 연결된 원본 사본과 SHA-256, 대상 식별, 발행자, 문서번호, 발행/유효일, 외부 문서상 결정을 보존한다. PDF/PNG/JPEG 10MB 이하를 저장하며 원본 다운로드는 계획 소유/출력 권한과 실제 바이트 해시를 검사한다. 같은 범주·대상의 최신 기록으로 범주 존재 여부만 점검하고 만료/거절을 제외한다. 과거 자료는 API에서 수정/삭제하지 않는다. 기존 DB 테이블을 사용하여 V10/25개 테이블을 유지한다. 외부 문서 진위·모든 화물/장비별 증빙 완전성·실제 운송 승인과 자동 계획 변경은 제공하지 않는다. E01은 여전히 진행/검증 대기이며 전체35·완료32·미완료3을 유지한다.


## OOG 핵심 범위 정정과 연성 구조 계산

냉동·탱크 전용 운용은 사용자의 OOG 의도보다 넓게 확장한 항목이므로 S01을 핵심 기능과 집계에서 제외한다. 실험 코드와 계산 초안은 reference/experimental-special-equipment-20261014에 보존하고 실제 API는 REEFER/TANK 요청을 거부한다. 프로그램은 Dry/HC와 비교하는 OT/FR/Platform/Multi-FR/Breakbulk 계획에 집중한다. 따라서 현재 기능은 전체34·완료32·진행2·검증32통과/2대기다.

E04에 일정 EI 1차원 Euler-Bernoulli 보와 공면·간극0 압축 스프링의 연성 FEM을 추가했다. 최대 8지지/16하중의 접촉 집합을 검사하고 평형/접촉 잔차를 만족하는 해만 반환한다. 구간 Hermite 3차식의 내부 처짐 극값도 계산한다. 3D 장비 전체/비틀림/좌굴/피로/국부 접합부는 미구현이므로 E04 전체 완료로 처리하지 않는다. E01은 실제 파일 해시를 검증한 계획·증빙·수치/결정 기록 ZIP 출력까지 구현했으며 실제 자료 대조/진위/선사 승인 연계는 대기다.

정식 보 요소 근거: [TU Delft Euler-Bernoulli beam elements](https://interactivetextbooks.citg.tudelft.nl/computational-modelling/structural_linear/euler_bernouilli.html). 이 자료의 선형 보 요소를 사용했다는 사실은 실제 장비의 구조 인증을 뜻하지 않는다. 모든 결과는 PRE_PLAN이다.


## 원본 제원 참고와 실측 대조 확장

18개 원본 통합문서(17 XLSX·HTML 형식 XLS 1), XLSX 27개 시트의 비어 있지 않은 셀/수식, 도형 텍스트와 내장 이미지 1개를 조사했다. 도형/셀이 표시하는 항목이 실제 구조 도면이나 증빙이라는 뜻은 아니다. 일반 장비 제원 이미지의 비냉동 8종을 참고 후보로 전사하고 현재 DB와 차이만 비교한다. 실제 확인 근거·계획 비율은 자동 채우지 않는다. 세부 조사 기록은 engineering-source-inventory.json이다.

MEASUREMENT_CHECK는 같은 계획/회사에 속하는 최신·미만료 증빙 원본 해시를 검사하고, 사용자가 독립 입력한 포장 치수/중량 또는 계산 CoG/중량을 저장 사본과 대조한다. 잘못된 범주/대상·교체된 문서·변조 파일은 차단한다. 추정/불일치는 새 확인 사본 필요로 기록하며 저장 계획/계산을 변경하거나 실제 승인하지 않는다. 결과와 출처 바인딩은 검토 ZIP에 포함한다. E01의 실제 자료 진위/실물 대조/선사 연계와 E04의 실제 장비 전체 구조 검증은 계속 미완료로 유지한다.
