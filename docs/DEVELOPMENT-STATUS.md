# OOG 개발 진행 기록

## 병렬 기능 구현 및 수치 현황 2026년 10월 13일

등록 기능 25개 중 완료 18·미완료 7(진행 3·미착수 4), 기능 검증 통과 17·대기 8이다. 완료는 기능표에 명시한 내부 개발 범위이며 실무/선사/공학 승인과 구분한다. docs/feature-status.json을 단일 원본으로 FEATURE-STATUS.md와 API classpath 자원을 생성한다. 대시보드와 업무 안내 화면은 동일 API에서 합계를 계산해 표시한다.

P03 원치수/포장치수 입력·매핑 분리, I04 병합 1/2행 헤더 자동 제안·개당/행합계 중량, L04 기존 장비 간 Move/Lock 및 불변 개정, O03 전체 시나리오 CLP Excel 및 3면 개략도, H01 원본·계획·감사 이력 조회/원본 다운로드를 병렬 구현하고 통합했다. 잘못된 JSON·불완전한 원치수·수량 없는 행합계·중복 오류와 저장 실패 전체 롤백을 보호한다.

Java 단위 검사 20건·실패 0, Python 4건, 실제 oog DB/API 검사 39건, 프런트 TypeScript/build 통과. API 검사에 원본 사본 불변·명시적 잠금 해제·겹침/한도/회전 거부·다른 프로젝트 파일/계획 거부·전체 Excel 시나리오 및 미배정 보존·개발 수치 합계를 포함한다. 검증용 프로젝트/파일/업무 자료는 정리했고 Flyway V2를 유지한다. 매뉴얼 v0.2·11페이지 생성·Word 렌더링. UI 직접 업무 조작은 미검증이며 L03을 검증 대기로 유지한다. [검증 기록](verification-parallel.json).

## B01–B04 초기 기반 실행 검증 2026년 10월 13일

신규 초기 구현의 Java build·경계 테스트 1, 프런트 TypeScript/build, Python 테스트 4와 실제 DB/API 검사 19건이 통과했다. 실제 Excel 3품목 가져오기, 중복 전체 거부, 판정·CLP 저장/재조회·수량 보존·Excel 출력·감사 확인 후 검증 자료를 정리했다. public의 oog_ 6·core_ 1, Flyway V2를 확인했다. 사용자 매뉴얼 JSON에서 Word v0.1·8페이지를 생성해 전체 렌더링·시각 검수했다.

이번은 초기 기반 범위 검증이며 전체 문서 MVP 완료가 아니다. JWT/RBAC·회사 경계·수동 Move/Lock·OR-Tools·다중 Rule·CLP Excel·견적은 미구현으로 유지한다. 초기 장비값의 선사 승인은 별도다.

검증 방식은 자동화 코드와 실제 백엔드 API다. UI는 로그인 페이지 표시만 확인했고 로그인 이후 업무 조작은 미검증이다. API 성공을 전체 UI 성공으로 기록하지 않는다.

## 업무 공통 접두어 통일 2026년 10월 13일

사용자 결정에 따라 업무 테이블은 oog_, 공통 테이블은 core_로 통일한다. 적용된 V1을 수정하지 않고 V2에서 기존 7개 테이블을 이름 변경한다. 공통 감사는 core_audit_history이며 업무 6개는 oog_다. 인증 이식 때 공통 사용자·회사·권한을 core_로 추가한다. 기존 데이터와 FK를 유지하고 실제 적용 여부를 검증한다.

## 신규 제품 기반 2026년 10월 13일

제공된 제품 기획 v0.1과 기술 아키텍처 v0.2를 확인했다. 기존 circle-oog는 다른 개발자 소스이므로 reference/legacy-20261013으로 이동하고 신규 backend/frontend/optimizer를 만들었다. 루트 Git 이력은 보존했다.

사용자 결정으로 FMS common의 응답·페이지·CBM을 shared-core로 재사용한다. core 모듈 자체에는 구현이 없으며 FMS auth/system의 현재 사용자·회사·상품권한 결합은 별도 이식 범위로 기록했다.

프로젝트·화물·Excel 매핑·기본 검증·OOG 분석·장비 후보·DEFAULT Rule·보수적 CLP·2D·분석 Excel·업로드/시나리오/감사 저장 코드를 작성했다. 실측 장비 제원 승인, 수동 조정, OR-Tools, CLP Excel, JWT/RBAC, 회사 경계는 미완료다. 검증 결과는 VERIFICATION.md와 verification-foundation.json에 별도로 기록한다.
